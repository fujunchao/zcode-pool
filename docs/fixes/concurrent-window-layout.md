# 并发注册窗口优化方案（v0.2.13）

## 已确认的问题

1. 原始前端调度离线回放：两个任务同时结束后，配置并发 2 会补出 3 个任务。
   后端只在异步初始化之前数已建窗口，也未计入在途请求。
2. 按现有测试尺寸 500×734 计算，1080p 五并发的第二行底部达到 1488px。
3. 三并发暂时剩两扇时整理，缓存变成两列，后续补位错误进入第二行。
4. 窗口允许调整尺寸，但重排只抽样一扇外框；物理尺寸也未按目标屏幕缩放换算。
5. 重排窗口快照与清空槽位不是一个串行操作，存在丢失新分配槽位的时序风险。

## 实施顺序与验收标准

- [x] 调度：单批次调度不可重入，启动中任务预占并发名额；旧批次定时器、迟到的
  初始化响应不能污染新批次。后端预占名额覆盖初始化至窗口销毁，任何失败均释放。
- [x] 布局：提取统一窗口管理模块，槽位分配、释放、缓存与手动重排保持一致。
  普通补位只操作新窗口，复用最小空闲槽位；已有窗口不被动移动或缩放。
- [x] 可见性：基于显示器 work_area 和目标屏幕缩放计算逻辑尺寸；优先平铺，
  放不下则在工作区内层叠，必要时缩小窗口以适配屏幕，不向屏外新增行。
- [x] 整理：保留本会话预计容量（包含尚未建窗的名额），按稳定槽位顺序整理；
  统一恢复窗口尺寸。用户主动调整旧窗口后不保证自动零重叠，主动整理负责归位。
- [x] 系统适配：定位与重排在主线程串行执行；缓存的显示器、工作区或缩放失效时，
  只重算新窗口的布局，不打断已有验证码操作。先定位后显示，批量窗口不抢焦点。
- [x] 错误反馈：定位失败不得留下不可见窗口；整理失败通过现有提示与脱敏日志反馈。
- [ ] 验证与发行：回归通过后同步版本，推送 main 和 v0.2.13 标签；所有目标平台附件
  构建成功后公开 Release 草稿。

## 测试入口

1. 原始 mbox.js 的公开操作（加载、选择、启动、完成、停止）及 IPC 输出；替代时钟和
   宿主连接，不复制 pump 算法。覆盖同时完成、慢初始化、失败、停止后重启。
2. 窗口管理模块的预占、落位、重排、释放接口与返回矩形；验证容量、唯一槽位、
   旧窗口稳定、工作区包含关系、不同缩放和负坐标显示器、手动整理与补位。
3. 原生 Tauri/WebView2 的本地空白窗口，不调用真实 OAuth、不读取账号库：验证尺寸、
   坐标、补位不移动旧窗口，以及整理后的实际可见区域。
4. 保留现有授权回调、权限和前端进度回归；完整 Rust 测试、前端构建与安装包只在
   GitHub Actions 执行。本机运行轻量 Node 回放和静态检查，不构建发行产物。

## 实施补充

- `login_windows/layout.rs` 只负责容量、固定槽位与几何计划；原生适配层以异步操作锁
  串行化开窗/整理，状态短锁不覆盖窗口事件等待，销毁回调不等待异步操作锁。
- 尺寸/位置设置返回不代表原生事件已经生效。Windows/macOS/Linux 都在事件循环推进后
  检查实际结果；GTK 恢复最大化导致装饰边距变化时重新提交同一目标尺寸，不用旧外框
  差值连续缩小窗口。未收到首个有效几何事件的隐藏窗口不能视为已经落位。
- macOS 后台显示使用 `orderFront`，不使用会抢焦点的 `makeKeyAndOrderFront`；混合缩放
  跨屏位置按目标显示器尺度换成逻辑坐标，不依赖移动前的缩放。
- Linux 根据实际 GDK Display 类型区分 X11/Wayland。X11 校验绝对坐标；Wayland 没有
  客户端全局定位能力，位置由合成器决定，只约束窗口大小，不因缺少全局坐标拒绝登录。
  工作区/缩放矩阵仍有纯逻辑测试，CI 不冒充真实混合 DPI 多屏实测。
- 页面可能先于开窗响应发出单次填表请求或最终结果。前端按 flow 暂存早期事件，最多
  10 个流程、每个 200 条、保留 120 秒；原子绑定批次邮箱后重放，终态优先于旧请求。
  主界面完整透传成功/失败结果，OAuth 通知与重放结果共用幂等收口。
- 原生测试使用独立退出码，避免 macOS 事件循环返回值导致失败假绿。所有显示器查询
  在主线程完成，避免测试本身跨线程调用 GDK。补位测试比较槽位坐标，已有窗口检查
  完整矩形；整理另外验证客户区尺寸一致，不把不同窗口的系统装饰差异当作槽位变化。
