# 授权回调卡住修复计划（v0.2.12）

## 现象与证据

网页显示“授权成功，正在跳转到应用”，但账号没有入库，最终 OAuth 流程过期。
既有日志及原始驱动离线回放表明：授权回调开始后，驱动仍可能通过修改顶层
`location.href` 上报 `done`，与业务导航竞争。离线回放确认了竞争时序；现有日志
没有原生导航错误码，不能据此断言所有同类失败都由该原因造成。

## 修复范围

- [x] 使用独立、最小权限的 Tauri IPC 插件接收登录窗口消息，彻底移除导航式上报。
- [x] 宿主按窗口绑定流程，不信任网页传来的 flow；仅允许登录站点调用消息接口。
- [x] 点击授权后进入“等待授权回调”；只有后台成功入库才标记完成。
- [x] 补充脱敏导航/加载日志，区分服务端等待与可重试的轮询网络错误。
- [x] 保留现有深链接与轮询双通道、人工验证码流程、固定窗口槽位及超时上限。

不增加自动重放一次性授权码、不改邮箱密码或真实账号、不延长超时来掩盖问题。

## 回归边界

沿已确认的诊断边界测试，而不是复制实现：

1. 原始注册驱动的页面输入与宿主消息输出：快速/慢速回调、IPC 延迟/不可用、真实业务导航。
2. 登录消息接收接口：消息白名单、窗口与流程归属、远程最小权限及敏感参数脱敏。
3. OAuth 轮询接口：正常等待、临时网络/HTTP 错误、成功、过期与终止错误。
4. 前端完成事件：等待回调不能显示“入库完成”，失败与成功分别收口。

## 预防同类问题

进程间消息不能复用业务导航；流程终态应由宿主保存结果决定，而不是由网页按钮决定。
测试除纯函数和时序回放外，保留真实 IPC 权限与原生 WebView 冒烟边界。
