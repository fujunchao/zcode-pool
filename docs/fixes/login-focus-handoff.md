# 注册窗口关闭时的焦点交接（v0.2.16）

## 已确认的触发链

2026-10-16 在 Windows / v0.2.15 上，由用户实际注册配合四分钟只读 WinEvent
记录复现。21:37:21 新补位窗已经显示，但焦点仍在旧注册窗；21:37:25.271
旧焦点窗成功入库并开始关闭，21:37:25.288 主界面获得前台、遮住仍可见的新窗。
另外两扇补位窗直到 21:37:26 / 28 才显示。主界面 `topmost=false`，不是常驻置顶。

完成处理直接 `close()`，原生关闭没有焦点交接；补位又刻意不激活新窗。此前
回归只验证“关闭非焦点窗不会干扰另一扇旧窗”，遗漏了“当前焦点窗关闭后，
剩余新窗从未激活”的路径。只读记录的主界面前置断言失败一次，记录已停止，
未操作账号或把邮箱/输入内容写入诊断文件。

## 修复设计

1. **统一生命周期入口。** 注册窗创建后由窗口管理模块安装关闭/销毁监听；
   自动完成、失败、跳过以及标题栏关闭都走 `CloseRequested`，名额仍在
   `Destroyed` 归还。不开启置顶、不重排窗口、不改变注册流程和补位节奏。
2. **只修复已证实的 Windows 路径。** 在原生关闭前读取实际前台 HWND，只有
   当前窗口仍是前台时才尝试交接。直接使用普通 `SetForegroundWindow`，不用
   模拟按键、强制激活或延迟重试；保持 macOS、X11 与 Wayland 原有行为。
3. **选取安全目标。** 按固定槽位顺序选下一扇已经落位、仍可见且未最小化的
   注册窗，排除当前窗口和初始化中的预占。提交前再次检查前台，操作后确认
   实际焦点；用户已切走就停止，不能把焦点抢回来。无合适目标时正常关闭。
4. **真实接线回归。** 原生测试使用与产品相同的生命周期入口，复现旧窗连续
   完成、新窗从未激活的现场；断言主界面不能瞬间获得焦点，而不只是检查最终状态。
   保留既有非焦点关闭、补位不挪窗、整理与多平台原生回归。
5. **可诊断但不泄露内容。** 记录关闭时焦点交接的结果及截短流程标识，不记录
   邮箱、网页输入、授权链接或凭据；失败不阻止正常收口或名额释放。

## 验证与发布顺序

- 在 `codex/reg-focus-handoff` 分支先加入原生失败用例，确认旧逻辑确实暴露缺陷。

  与静态检查；完整 Tauri/原生窗口和发行包构建仍由 GitHub Actions 执行。
- 三平台回归通过后合入并推送 main；同步 package、Tauri、Cargo、锁文件及发布
  工作流版本为 0.2.16。主分支校验通过后推送不可变标签。
- 五件发行附件（Windows 安装版/便携版、macOS Universal、Linux DEB/AppImage）
  均构建成功，核对名称、版本、上传状态、大小和 SHA-256 后公开发布。
